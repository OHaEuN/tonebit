# 톤빛 서비스 기획 문서

> 톤빛(https://tonebit.vercel.app)을 처음부터 기획자로 시작했다면 썼을 문서 여덟 가지. 지금 배포된 서비스(2026-11-11, master c54db24 기준)를 거꾸로 뜯어 적었다. 실제로는 아이디어를 내고 하루 만에 바이브 코딩으로 첫 버전을 만들었고 문서 없이 코드로 바로 갔다. 그래서 이 묶음은 "다음에 같은 걸 팀으로 한다면" 어떤 순서로 무엇을 정해야 하는지에 대한 기록이기도 하다.

| 순서 | 문서 | 답하는 질문 | 주로 읽는 사람 |
|---|---|---|---|
| 1 | [사전 시장조사](./01-market-research.md) | 이 시장에 들어갈 이유가 있나, 누가 이미 하고 있나 | 대표, 기획, 마케팅 |
| 2 | [서비스 기획서](./02-service-plan.md) | 누구의 어떤 문제를 어떻게 풀고, 성공은 무엇으로 재나 | 전원 |
| 3 | [요구사항 정의서](./03-requirements.md) | 무엇을 꼭 만들고 무엇은 안 만드나 | 개발, QA |
| 4 | [서비스 정책서](./04-policy.md) | 애매한 상황에서 서비스가 어떻게 판단하나 | 개발, CS, 법무 |
| 5 | [정보구조와 사용자 흐름](./05-ia-and-flow.md) | 화면이 어떻게 이어지고 어디서 갈라지나 | 디자인, 개발 |
| 6 | [화면설계서](./06-screen-spec.md) | 각 화면에 무엇이 있고 눌렀을 때 무슨 일이 나나 | 디자인, 개발, QA |
| 7 | [지표와 이벤트 설계](./07-metrics-and-events.md) | 잘 되고 있는지 무엇으로 알고 어떻게 남기나 | 기획, 데이터 |
| 8 | [출시·운영 계획](./08-launch-and-ops.md) | 언제 무엇을 확인하고 내보내며, 무엇이 위험한가 | 전원 |
| 9 | [셀프 리뷰](./09-self-review.md) | 문서를 쓰고 나니 제품의 어디가 비어 있었고, 무엇을 고쳤나 | 전원 |

시장 숫자는 출처 페이지를 직접 열어 확인한 것만 링크를 달았고, 확인하지 못한 값은 "추정"이라고 적었다. 서비스 쪽 사실은 전부 지금 코드와 저장소의 `docs/` 폴더에서 가져왔다. 다이어그램은 mermaid라 GitHub, VS Code, Obsidian에서 그려진다.
