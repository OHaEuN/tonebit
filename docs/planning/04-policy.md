# 4. 서비스 정책서

> **원칙:** 얼굴은 기기 밖으로 안 나간다. 판정은 근거와 함께 보여 준다. 사람과 무관하게 한 방향으로만 미는 기준은 두지 않는다. 돈은 쓰지 않고, 수익은 쿠팡 파트너스 링크만.

기준일 2026-11-11. 정책 ID는 P-영역-번호. 코드에서 상수로 고정된 값은 괄호에 적었다.

---

## 1. 사진과 측정

| ID | 정책 |
|---|---|
| P-SHOT-01 | 사진과 카메라 프레임은 브라우저 안에서만 처리한다. 서버로 보내는 사진은 없다. |
| P-SHOT-02 | 한 번에 올릴 수 있는 사진은 5장(`MAX_SHOTS`)까지다. 넘치면 앞에서부터 5장만 쓰고 몇 장을 뺐는지 알린다. 권하는 장수는 3장(`RECOMMENDED_SHOTS`)이며 그 아래면 "(n/3)"을 보여 준다. |
| P-SHOT-03 | 여러 장을 올리면 다 본 뒤 한 번에 판정한다. 첫 장 결과가 떴다가 바뀌지 않는다. 보는 동안 "사진을 보는 중… N%"를 보여 준다. |
| P-SHOT-04 | 얼굴을 못 찾은 사진은 빼고 합친다. 전부 실패하면 "얼굴을 찾지 못했어요" 또는 "피부색을 읽지 못했어요"를 보여 주고 측정 전 화면으로 돌아간다. |
| P-SHOT-05 | 카메라 측정은 얼굴이 잡힌 뒤에만 시작할 수 있고, 20프레임(`MEASURE_FRAMES`)의 중앙값을 쓴다. 보정된 프레임과 안 된 프레임이 섞이면 많은 쪽만 쓴다. |
| P-SHOT-06 | 조명 점검은 어두움·역광·색 편향(주황·푸른·초록)·얼굴 작음을 본다. 측정을 막지는 않고 알리기만 한다. |
| P-SHOT-07 | 사진은 EXIF 회전을 브라우저 기본에 맡긴다. 분석 해상도는 화면 표시보다 크게 잡는다(`STILL_ANALYSIS_WIDTH`). 치아·흰자 기준은 픽셀 수가 생명이기 때문이다. |

## 2. 판정

| ID | 정책 |
|---|---|
| P-TONE-01 | 결과는 12톤(4시즌 × 라이트·브라이트·트루·소프트·딥 중 시즌별 3개) 중 하나다. 웜·쿨은 피부 색상각으로, 뉴트럴 구간이면 노란기(b*)로 웜·쿨을 가른다. 라이트·딥은 ITA, 클리어·뮤트는 채도로 본다. |
| P-TONE-02 | 뉴트럴인데 웜·쿨 시즌이 나오면 이유를 한 문장으로 적는다("노란기가 조금 더 있어 웜 쪽으로 봤어요"). 시즌 이름과 언더톤 문장이 어긋나 보이지 않게 한다. |
| P-TONE-03 | 가능성 %는 시즌 확률이고 다음 후보를 같이 보여 준다. 확신도는 축 경계까지의 거리로 높음·보통·낮음이며, 배경 기준 보정이면 보통까지만 준다. |
| P-TONE-04 | 여러 장은 Lab 채널별 중앙값으로 판정한다. 장마다 시즌이 갈리면 확신도를 낮음으로 내리고 "사진마다 결과가 갈려서 가운데 값으로 판정했어요"라고 알린다. 합친 값은 가장 약한 보정 기준만큼만 믿는다. |
| P-TONE-05 | 이용자는 합친 결과와 사진 한 장씩의 결과를 탭으로 오갈 수 있다. 한 장을 보는 동안은 "이 사진 한 장만 본 결과예요. 합친 결과가 더 믿을 만해요"를 붙인다. 다음 단계는 그때 보고 있는 결과로 간다. |
| P-TONE-06 | 판정 기준값(색상각 중심, 뉴트럴 황색도, ITA 경계)은 전문가 진단 데이터로 매주 다시 맞춘다. 50건 미만이거나 교차검증 이득이 2%p 미만이면 바꾸지 않고, 한 번에 움직이는 폭은 색상각 ±3°, 황색도 ±4, ITA ±8°로 묶는다. 바뀐 값은 PR로 올리고 사람이 머지한다. |
| P-TONE-07 | 결과는 "재미로 보는 테스트"다. 조명과 화장에 따라 달라질 수 있다고 내 톤 화면에 적고, 의료·피부 질환 판단으로 읽히는 표현은 쓰지 않는다. |

## 3. 조명 보정

| ID | 정책 |
|---|---|
| P-LIGHT-01 | 보정 기준의 우선순위는 흰 종이 고정(카메라) → 이용자가 찍은 흰색 → 치아·눈 흰자 → 배경(절반) → 없음이다. 사진마다 쓴 기준을 기록하고, "왜 이렇게 나왔나요"와 "측정값 자세히"에 적는다. |
| P-LIGHT-02 | 치아·흰자는 피부보다 1.05배 이상 밝고 선형 채도가 0.6 이하일 때만 믿는다(감은 눈, 그늘진 입, 입술, 충혈 제외). |
| P-LIGHT-03 | 배경 기준은 벽·옷 색이 섞이므로 로그 공간에서 절반만 되돌리고 게인을 0.5~2배로 묶는다. |
| P-LIGHT-04 | 이용자가 누른 흰색은 피부보다 밝아야 하고, 하얗게 날아갔거나 색이 있으면 거절하고 이유를 알린다. 자동으로 찾은 흰색 후보는 이미 치아·흰자·흰 종이 기준이 있으면 제안하지 않는다(회색 벽을 흰색으로 맞추면 밝은 쪽으로 튀기 때문). |
| P-LIGHT-05 | 형광등·전구색·푸른 조명이 잡혔고 완전 보정이 아니면 "흰색 기준으로 더 정확하게"를 펼쳐 두고 권한다. 그 외엔 접어 둔다. |
| P-LIGHT-06 | 흰색 기준은 사진마다 따로 맞춘다. 여러 장일 때는 위에서 사진을 고른 뒤 맞추라고 안내한다. |

## 4. 추천과 점수

| ID | 정책 |
|---|---|
| P-REC-01 | 어울림 점수는 아홉 각도(밝기, 언더톤, 붉은기, 채도, 조화, 시즌 맞춤, 유행, 인상, 질감)의 가중합이다. 1등이 80점대이고 100점은 없다. 분포는 합성 얼굴 여섯 유형으로 재서 상위 1위 80~89, 중앙값 57~79를 유지한다. |
| P-REC-02 | 사람과 무관하게 한 방향으로만 미는 항은 두지 않는다. 치아가 하얘 보이는 정도(블루 베이스 레드 선호)를 뺀 이유가 이것이다. 최적점은 사람마다 다르다. |
| P-REC-03 | 취향 질문의 답은 가중치의 출발점이 되고, 답하지 않아 쓰지 않는 항목은 가중치를 0으로 둔다. |
| P-REC-04 | 둘 중 고르기는 8강 일곱 번이며 Bradley–Terry 방식으로 배울 수 있는 다섯 축의 가중치를 갱신한다. 한 축이 전체의 25%(`MIN_SHARE`) 아래로 내려가지 않고, 사전 강도 12(`PRIOR_STRENGTH`)로 일곱 번 안에 과하게 쏠리지 않게 한다. 건너뛰면 기본 가중치로 순위를 낸다. |
| P-REC-05 | 고르기 뒤 순위에는 고르기 전 순위와의 차이를 ▲▼로 보여 준다. 끝까지 이긴 립이 AI 1등과 같은지 이벤트로 남긴다. |
| P-REC-06 | 꼴찌 비교는 인기 제품 중 점수가 가장 낮은 것과 1등을 나란히 보여 준다. 꼴찌라고 해서 나쁜 제품이라는 뜻이 아니라 내 피부에 덜 맞는다는 뜻이라고 읽히게 쓴다. |
| P-REC-07 | 발색은 선형 RGB에서 섞고, 사진의 조명(카메라 흰색)을 반영한다. 색은 브랜드 공식 칩 기준이라 실제 발색과 다를 수 있다고 결과 카드에 적는다. |

## 5. 제품 데이터와 링크

| ID | 정책 |
|---|---|
| P-DATA-01 | 제품은 `products.json`에 두고(2026-11-11 기준 204개: 립과 블러셔), 필드는 브랜드·이름·색 이름·hex·질감·시즌·가격대·유행 순위·색 출처다. 쇼핑몰을 크롤링하지 않는다. |
| P-DATA-02 | 색 hex는 브랜드 공식 칩을 우선하고 출처를 필드에 적는다. 없으면 흰 종이 스와치로 잰 값을 쓴다. |
| P-DATA-03 | 유행 순위는 공개된 베스트 목록을 분기마다 갱신한다. 단종·품절은 갱신 때 뺀다. |
| P-DATA-04 | 구매 링크는 쿠팡 파트너스 링크만 쓴다. 링크마다 제품 id, 어느 화면(순위·비교·발라 보기·결과·AI 상담), 순위면 몇 위를 데이터 속성으로 남긴다. |
| P-DATA-05 | 이용자가 잰 "내 제품 색"은 hex와 이름만 그 브라우저(localStorage)에 남긴다. 사진은 저장하지 않는다. |

## 6. 개인정보와 데이터

| ID | 정책 |
|---|---|
| P-PRIV-01 | 얼굴 이미지와 랜드마크는 브라우저 밖으로 나가지 않는다. CSP `connect-src 'self'`로 브라우저가 다른 곳에 요청하지 못하게 막는다. |
| P-PRIV-02 | 분석 이벤트에는 얼굴·측정 수치를 싣지 않는다. 톤 이름, 확신도, 단계 이름, 제품 id만 보낸다. 쿠키와 개인 식별은 없다. |
| P-PRIV-03 | 전문가 진단 제출은 동의 뒤에 측정 숫자(Lab, ITA, 색상각, 보정 기준)와 진단 톤만 저장한다. 글과 사진은 받지 않는다. |
| P-PRIV-04 | AI 상담은 진단 숫자와 질문만 보낸다. 무료 등급 입력이 서비스 개선에 쓰일 수 있어 사진은 절대 보내지 않는다. |
| P-PRIV-05 | 반응(비슷해요 등)과 상담 평가(도움이 됐어요 등)는 판정·보정 기준 또는 답에 붙은 제품 id만 남긴다. |
| P-PRIV-06 | 개인정보처리방침은 /privacy에 두고 얼굴 이미지, 진단 결과 보내기, AI 상담, 쿠키와 저장소, 제휴 링크, 호스팅과 접속 기록, 문의를 항목으로 적는다. 문의는 GitHub 이슈로 받고 연락처는 싣지 않는다. |

## 8. AI 상담

## 10. 예외와 오류

| 상황 | 서비스의 판단 |
|---|---|
| 카메라 권한 거부·미지원 | "카메라 권한이 거부됐어요"를 보여 주고 사진 올리기 버튼을 주 행동으로 바꾼다 |
| 얼굴 인식 모델 로드 실패 | 다시 시도 버튼, 진행률 표시 |
| 얼굴 없음·피부색 못 읽음 | 안내 문구, 보고 있던 결과는 유지 |
| 5장 초과 | 앞 5장만 쓰고 "몇 장은 뺐어요" |
| 사진마다 시즌이 갈림 | 가운데 값으로 판정, 확신도 낮음, 한 장씩 볼 수 있게 |
| 조명 색이 섞임 | 흰색 기준 맞추기를 펼쳐 권함 |
| 둘 중 고르기에 얼굴 사진이 없음 | "얼굴 사진이 없어요. 측정을 다시 하면 둘 중 고르기를 할 수 있어요", 건너뛰기 제공 |
| DB·Gemini 값 없음 | 해당 기능(피드백·상담)만 꺼지고 나머지는 동작 |
| AI 한도 초과·장애 | 검색만으로 답하는 폴백 |
| 브라우저 뒤로 가기 | 이전 단계 화면으로. 첫 단계는 replace, 다음부터 push |
